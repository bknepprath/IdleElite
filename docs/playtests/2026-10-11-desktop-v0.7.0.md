# Idle Elite v0.7.0 desktop validation

Date: October 11, 2026.

## Implementation

The production `res://scenes/main.tscn` now supports a landscape desktop layout. Windows starts at 1600x900; Web follows the browser canvas. Android retains its 1080x1920 viewport stretch configuration and compatibility renderer. Desktop layout selection is excluded on Android.

- Three independently scrollable, selectable production skill pages at widths of at least 1200 pixels. A smaller landscape window uses two pages. Opening Chat / High Scores removes one page. The social panel is closed by default.
- Each column uses the existing activity controls, lists, gauges, and production input handlers. One shared simulation still owns progression, timers, saves, and reward rules. Keyboard dropdown selection swaps duplicate skills rather than rendering the same skill twice.
- Existing tutorials retain their navigation gates and use one skill page until onboarding is complete. Stale queued help notes now check their seen flag and skill before opening.
- The hub projects existing positions across the available width without stretching the art; saved positions retain canonical mobile coordinates.
- Chat and scores use the existing backend, categories, request gates, and identity protections. Closed desktop chat disconnects its stream and stops its refresh timer. Shared high scores do not imply new cross-device Google login support.
- Desktop list caches are explicitly released on navigation. The Android swipe path remains active only in the portrait layout.
- The prepared v0.6.2 stability changes and the Fight A Shark opportunity-input fix are carried forward. See `play-store/docs/launch-readiness-2026-10-11-v0.6.2.md` for the original root causes and limitations.

## 30-minute desktop soak

Completed all 1800 seconds and exited successfully; no agent-owned Godot process remained. The production scene cycled through three skills, docked Chat, docked Scores, Hub, and Settings every 15 seconds while an activity ran. Online requests were disabled. This is a headless CPU/node-lifetime diagnostic, not the required live browser/GPU acceptance run.

At matching low-node checkpoints, nodes settled at 384 by minute 21 and stayed there through minute 30. Orphans returned to zero at each such checkpoint; a repeatable 460 detached cached nodes appeared in an intermediate navigation state and were released on the next cycle. Processed tweens returned to zero on the settled screen. Static memory at that checkpoint was 119,098,039 bytes at minute 21 and 119,107,427 at minute 30 (9,388 bytes difference). From minute 3 to minute 30 it grew about 3.0% while assets warmed, then plateaued. Final frame p99 was 17.031 ms; the whole run's maximum observed frame was 656.074 ms during concurrent validation/export work. This run does not clear the existing scroll/swipe frame-budget failures or prove all freezes are fixed.

The soak loaded the desktop core before the final tutorial-toolbar visibility adjustment. The final code separately passed the complete visible desktop interaction test; the full final source manifest matched the exports. No further production changes were made after the final exports.
